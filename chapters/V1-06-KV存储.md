# 第一卷第 6 章：key-value 存储

## 学习目标与原文对齐

对应分区、复制、一致性、版本冲突、故障处理、读写路径。目标：解释一次读写依赖哪些副本，理解可用性与一致性条件，并追踪节点恢复。先修 V1-05。

## P0 交互一：副本、读写确认与网络分区

- 画面：客户端、协调节点、A/B/C 三副本；每个副本展示值与版本，旁边展示收到的确认数。
- 参数：N=3，R/W 各 1—3；通信延迟 0—3 步；可断开一条链路或隔离一个节点。先固定副本成员，避免引入额外成员变更机制。
- 操作：写 x=2、选择延迟到 C，随后读取；切换 R/W，观察请求是否完成、返回哪些版本以及版本选择的依据。
- 样例：初始全为 x=1，W=2 写入 A/B 成功；仅从 C 读取 R=1 得到旧值。R=2 读 A/C 时能看到新旧版本，按本实验单写者版本号规则选新值。
- 反馈：把“确认成功”“所有副本一致”“读到新值”分开。隔离时显示哪些请求无法满足门槛，不笼统贴 AP/CP 标签。
- 关键边界：R+W>N 说明固定副本集合下读写集合相交，不独立证明并发写、故障和任意实现下的线性一致性。

## P1 交互二：冲突与恢复路径

- 初始：两个客户端读取同一购物车版本，在隔离侧分别加入不同商品。
- 操作：逐步推进两个写入，查看简化向量时钟是否可比较；选择覆盖策略或保留并发版本供业务合并。
- 反馈：覆盖可能丢掉一次添加；合并保留两个版本的变更，但提示删除操作不能简单集合并集。
- 恢复：分别观看提示移交、读修复、Merkle 树差异定位的小分镜；读写存储面板展示提交日志、内存表、磁盘表与查找过滤过程。Bloom filter 命中只表示“可能存在”。
- 范围：这些恢复机制分场景讲解，不假设所有 KV 产品同时采用同一组合。

## 思维导图

- API 与分区 → get/put、键空间、哈希环。
- 复制与确认 → N/R/W、协调者、延迟。
- 一致性 → 陈旧读取、分区、版本选择、保证前提。
- 冲突 → 因果、并发版本、业务合并。
- 恢复 → 故障检测、提示移交、读修复、反熵。
- 存储路径 → 日志、内存表、磁盘表、Bloom filter。

## 额外学习内容与练习

增加 CAP 场景判断卡、读写路径叠层图和“相交不等于全部保证”的反例说明。

1. 预测题：样例中只读 C 返回什么？答案：旧值 1。
2. 流程题：写确认与后台复制是什么关系？要点：达到 W 不等于 N 全完成。
3. 诊断题：两个购物车版本为什么不能按时间简单覆盖？要点：并发更新可能独立且都有效。
4. 取舍题：要求更少陈旧读取时会付出什么代价？要点：等待、可用性、协调复杂度，必须结合机制。

## 验收与边界

事件表可解释每次返回；网络分区与节点宕机分开标注；不从教学模型推导真实数据库承诺；恢复后能够检查副本值和版本。每种进阶机制均有独立小节映射与简化说明。
