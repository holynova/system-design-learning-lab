# 第二卷第 7 章：酒店预订系统

## 学习目标与原文对齐

对应库存数据模型、重复预订、并发锁、约束、分片、缓存与服务间一致性。目标：逐步解释最后一间房竞争与跨日期库存更新。先修 V1-06、V2-04。

## P0 交互一：两人抢最后一间房

- 初始：同一房型同一晚库存剩 1，A/B 两个请求；画面为事务泳道、库存行、订单表。
- 操作：交错执行读库存、检查、扣减、写订单；切换无保护、悲观锁、版本号乐观更新、条件更新/约束。
- 样例：无保护下 A/B 都读到 1 并各自成功，出现两张订单；安全版本只允许一个成功，另一个收到库存冲突。
- 反馈：高亮锁等待、版本变化、影响行数、提交/回滚；不能仅让最终库存非负就声称无超卖，还要核对成功订单数。
- 参数：并发 2—5、库存 1—3；默认不允许超售，允许业务超售作为独立策略讨论。

## P1 交互二：多晚预订与跨服务失败

- 初始：入住两晚，第一晚有房、第二晚无房；订单与库存更新作为一个明确事务单元。
- 操作：先尝试错误的逐日独立提交，再切换整体检查和事务提交；随后模拟支付失败、订单重试、取消。
- 反馈：正确模型下两晚要么全占用，要么都不占；重复请求沿用预订幂等标识，不产生新订单。跨服务取消用补偿状态，不假装数据库回滚能撤销所有外部行为。
- 缓存场景：查询页面展示旧库存 1，但确认阶段权威库存已为 0；反馈为售罄，而非继续按缓存确认。

## 思维导图

- 业务模型 → 酒店、房型、日期、库存、预订。
- 查询 → 搜索、缓存、价格、可用性。
- 确认 → 事务、锁、版本、条件更新、幂等。
- 生命周期 → 创建、确认、取消、补偿。
- 扩展 → 酒店分片、热点日期、缓存新鲜度。

## 额外学习内容与练习

增加并发步骤排序台、跨日期库存日历与“缓存可售不等于预订保证”卡。

1. 预测题：一间房两请求正确结果？答案：至多一张有效成功订单。
2. 排序题：多晚预订为何需要统一成功条件？要点：用户买的是整段入住，不是部分日期。
3. 诊断题：库存为 0 但已有两张订单，哪里错？要点：检查与写入竞态或重复请求。
4. 取舍题：悲观锁与乐观锁在高冲突下差别？要点：等待与重试，结合负载解释。

## 验收与边界

库存和订单一起核对；悲观锁展示等待和释放；乐观冲突不能自动算成功；多晚失败不残留部分占用；补偿失败进入待处理状态而非直接绿灯完成。
