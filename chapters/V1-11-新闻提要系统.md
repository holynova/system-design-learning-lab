# 第一卷第 11 章：新闻提要系统

## 学习目标与原文对齐

对应 Feed 发布、扇出、读取、社交关系与缓存。目标：解释写时扇出、读时拉取和混合方案为何适用于不同用户。先修 V1-01、10。

## P0 交互一：一条帖子如何到达关注者

- 初始：作者 A，有 5 位关注者；其中 2 人当前活跃。画面同时显示关系图、帖子存储、扇出队列和各用户 Feed ID 列表。
- 操作：A 发帖，再由关注者读取；切换推送、拉取、混合，使用同一事件序列重放。
- 参数：关注者 5/100/10000、活跃比例 0—100%、作者发帖次数 1—10；大人数以聚合节点表示。
- 反馈：推送模式显示写入多个 Feed 的次数；拉取模式显示读取时查询作者并合并的工作；混合模式列出哪些作者使用哪条路径。
- 样例：5 位关注者、发 1 条帖子，写时扇出产生 5 个 Feed 追加；读时拉取当时不产生这些追加，但读者打开页面时需要拉取并合并。把源帖写入与 Feed 追加分开计数。

## P1 交互二：名人热点与分页变化

- 操作：把 A 变成大号，限制扇出处理速率，观察队列积压；切换大号读时拉取。再在用户翻页期间插入新帖，对比偏移分页与游标分页。
- 反馈：展示排队造成的可见延迟、读取合并负担；分页面板高亮重复/跳过条目，明确游标依赖稳定排序键和查询条件。
- 扩展：模拟取关/删除，指出 Feed ID 缓存与源帖权限状态可能不一致；具体删除传播策略作为补充，不声称原文已完全覆盖。

## 思维导图

- 需求 → 时间顺序、关注关系、发布频率、读取频率。
- 发布 → 帖子存储、扇出服务、队列、Feed 缓存。
- 读取 → Feed ID、内容补全、合并、分页。
- 策略 → 写时推、读时拉、名人混合。
- 一致性与热点 → 延迟可见、删除、权限、热点账号。

## 额外学习内容与练习

增加“相同功能，不同读写成本”对照表和手工合并两个有序 Feed 的练习。排序算法与个性化推荐仅为可选专题，不扩大核心范围。

1. 预测题：5 个粉丝写时扇出需要几次 Feed 追加？答案：5 次。
2. 排序题：读取 Feed ID 后为何还要补内容？要点：索引与帖子内容分离。
3. 诊断题：大号发帖后普通作者可见性变慢？要点：共享扇出队列/资源拥塞。
4. 取舍题：全部改读时拉取是否总更便宜？要点：取决于读频率、关注数、缓存和合并成本。

## 验收与边界

三种模式共享关系与事件；只统计明确操作，不输出无依据延迟倍数；混合方案不重显同一帖子；分页进阶注明新增教学内容。
