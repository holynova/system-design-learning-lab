# 第二卷第 8 章：分布式邮件服务

## 学习目标与来源状态

原网站当前只有标题，没有可核对正文。本章为依据章名设计的独立补充规划，不声称对应原书小节。后续取得正文时核对协议、存储和搜索的覆盖范围。目标：区分邮件投递与邮箱读取，解释重试与多端状态。先修 V1-10、12、V2-04。

## P0 交互一：一封邮件跨服务投递

- 画面：发件客户端、提交服务、发送队列、域路由、接收服务、邮箱存储与收件客户端。
- 初始：A 向虚构域的 B 发邮件，包含小附件；给每一站显示当前处理状态。
- 操作：逐步推进，切换临时拒绝、永久拒绝、接收后响应丢失；暂停远端，再观察重试与队列。
- 参数：退避 1/2/4 模拟分钟、重试上限 3、附件 1/5/20 MiB；数值都是教学配置，不冒充邮件协议统一要求。
- 反馈：明确“提交成功”“远端接受”“写入邮箱”“被阅读”不同；远端接受后的响应丢失可能造成重复投递，不把一个 Message-ID 视为全网强制去重承诺。
- 恢复：临时失败可重试，永久失败转失败结果；不真实发送邮件。

## P1 交互二：邮箱、附件和多端同步

- 初始：手机和桌面共享一个邮箱，邮件正文和附件对象分开存放。
- 操作：手机标已读，桌面断线后移动邮件，再同步；查看按稳定邮件标识和版本恢复状态的流程。
- 反馈：正文不可变内容与“已读/文件夹”等可变元数据分开；冲突采用明确的演示规则并解释代价，不宣称复刻某一协议全部语义。
- 扩展：输入关键词，查看索引更新延迟导致“邮件已到但搜索暂未命中”；附件上传失败时不展示可用下载入口。

## 思维导图

- 业务 → 发送、接收、读取、搜索、附件。
- 投递 → 提交、域路由、队列、接受、失败。
- 存储 → 邮件标识、正文、附件、元数据。
- 多端 → 已读、文件夹、版本、增量同步。
- 可靠性 → 临时/永久失败、重试、重复、索引延迟。

## 额外学习内容与练习

增加“邮件系统与通知系统”职责比较、投递状态分镜；SMTP/IMAP 等术语只在对应机制卡解释，制作时核对正式规范。

1. 预测题：提交成功代表对方已读吗？答案：不代表。
2. 排序题：邮件投递与客户端读取在哪里衔接？要点：接收方邮箱持久存储。
3. 诊断题：邮件已在收件箱但搜不到？要点：索引同步可能延迟。
4. 取舍题：临时失败立即无限重试的问题？要点：拥塞、资源占用和延迟放大。
