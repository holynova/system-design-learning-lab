# 第二卷第 5 章：指标监控与告警系统

## 学习目标与原文对齐

对应指标模型、采集、推拉、传输、时序存储、压缩降采样、查询与告警。目标：追踪指标到通知，解释采样、高基数、抖动与缺数。先修 V1-10、V2-04。

## P0 交互一：一条指标到一条告警

- 画面：应用、采集器、队列、时序库、查询、规则引擎、通知；主图同步显示 CPU 时间曲线。
- 操作：注入 20 秒尖峰或 3 分钟持续高值；切换推/拉模型，调采集间隔 5/15/60 秒、阈值 70/80/90%、持续条件 0/30/60 秒。
- 样例：CPU 超过 80% 持续 20 秒，“持续 60 秒才告警”不触发；持续 90 秒且采样覆盖后触发，触发时刻取决于采集与规则评估周期。
- 反馈：规则状态从正常→待定→触发→恢复；另有“无数据”，不把采集失败当 CPU=0。

## P1 交互二：标签基数与降采样

- 初始：100 台机器、5 个端点、2 个状态标签，假设组合全部出现，1000 条序列。
- 操作：加入 1000 个用户值标签，理论组合增为 100 万；切换只看已出现组合，区分上界与实际值。
- 降采样操作：将 1 秒数据汇成 1 分钟平均值，比较最大值汇总；观察短尖峰被平均压低。
- 反馈：显示序列数、样本数和按固定字节假设估算的存储；计数器重置、直方图和 p99 仅作扩展解释，不把平均值直接转换为 p99。

## 思维导图

- 数据 → 指标名、时间、值、标签、基数。
- 采集 → 推/拉、发现、周期、缺数。
- 存储查询 → 队列、时序库、压缩、降采样、缓存。
- 告警 → 阈值、持续、分组、去重、恢复。
- 运维 → 告警噪声、延迟、监控自身、保留期。

## 额外学习内容与练习

增加“服务恢复”和“监控失联”对照图、告警疲劳案例和标签组合积木。

1. 预测题：20 秒尖峰会满足 60 秒持续条件吗？答案：不会。
2. 排序题：指标出现异常到通知间有哪些延迟？要点：采样、传输、评估、持续条件、发送。
3. 诊断题：所有曲线突然归零是否说明系统空闲？要点：先检查是否缺数据。
4. 取舍题：为何不给每条指标加 user_id？要点：基数与成本，视查询需求决定。

## 验收与边界

时间窗与采样对齐规则公开；标签上界和实际数量分开；告警状态可复现；平均值无法揭示的尖峰明确显示；不宣称教学工具完成生产监控。
