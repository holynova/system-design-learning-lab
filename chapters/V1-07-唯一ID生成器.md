# 第一卷第 7 章：分布式唯一 ID 生成器

## 学习目标与原文对齐

对应多主复制、UUID、Ticket 服务器、Snowflake 的时间戳和序列号。目标：区分唯一、趋势有序、全局严格顺序，并能解释机器标识和时钟的影响。先修 V1-02。

## P0 交互一：拆开一个 Snowflake ID

- 画面：64 位带标签的位条，显示符号位、41 位时间戳、5 位数据中心、5 位机器、12 位序列；旁边同步十进制与字段解释。
- 操作：调整模拟时间、数据中心和机器号，同一毫秒生成多个 ID；点击任一 ID 反向解码。
- 参数：数据中心/机器 0—31，序列 0—4095；普通界面只展示少量连续 ID，另有“一次生成 4097 个”预设。
- 样例：同一机器、同一毫秒生成序列 0 至 4095，第 4097 个等待下一毫秒；时间推进后序列归零。此处采用等待策略，其他策略列为对照说明。
- 反馈：高亮变化的位段，展示 2^12 个序列容量；不把机器号范围相同但分属不同数据中心的节点误判为重复。

## P1 交互二：时钟回拨与方案选择

- 操作：将时钟拨回 5 毫秒，切换等待恢复或拒绝生成；另设“错误配置：两个节点使用相同身份”，复现相同时间和序列导致碰撞。
- 反馈：显示生成被阻塞的原因、等待时间与已生成 ID；趋势有序示意同时显示不同机器的到达顺序，解释它不代表业务因果顺序。
- 比较卡：UUID、集中式序列服务、多主步长分配、Snowflake。输入是否要求数字、长度、离线生成、有序，显示可考虑方案和不满足条件；不自动指定唯一赢家。

## 思维导图

- 需求 → 唯一性、长度、格式、吞吐、有序程度。
- 候选方案 → UUID、Ticket、多主步长、Snowflake。
- 位布局 → 时间纪元、机器身份、序列容量。
- 异常 → 时钟回拨、序列耗尽、身份冲突。
- 取舍 → 协调成本、可用性、时间依赖、可解码性。

## 额外学习内容与练习

增加位数分配工作纸和“唯一不代表连续”的误区卡。P2 可调整机器位与序列位分配，观察容量此消彼长，但必须保持总位数约束。

1. 计算题：12 位序列同一毫秒最多多少值？答案：4096。
2. 流程题：达到序列上限后下一步是什么？要点：取决于明确策略，本实验等待时间推进。
3. 诊断题：为什么部署新机器后发生重复？要点：检查机器身份冲突及时间管理。
4. 取舍题：要求全局严格递增是否仅靠 Snowflake 足够？要点：不够，需要额外协调并评估代价。

## 验收与边界

计划要求未来数值展示保留 64 位精度；容量与位数对应；错误配置可控复现；不承诺 UUID 概率碰撞等于绝不碰撞。ID 中时间字段不被当作可靠业务事件时间。
